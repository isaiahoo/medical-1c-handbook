# Структура базы знаний для будущего помощника MAX

Бот не создан и не подключён. Источник знаний — errors.json, кодировка UTF-8. Верхний уровень содержит версию схемы, дату проверки, состояние исследования, правила поиска и массив errors. Версия схемы — 1.1. Идентификаторы 001–159 постоянны: новая карточка получает новый номер; старые номера не переиспользуются.

## Поля карточки

| Поле | Содержание |
| --- | --- |
| id, title, category | Постоянный номер, заголовок и повседневная задача врача |
| original_error_text | Точный известный текст; null, если надёжно не установлен |
| error_code | Код сообщения; null при отсутствии. Не номер вида СЭМД и не номер дефекта |
| error_codes | Все подтверждённые написания кодов сообщения; error_code сохраняет первый код для совместимости |
| rule_codes | Обозначения правил проверки СЭМД, например У1-52; не коды ответа сервера |
| status_codes | Числовые статусы проверки; не HTTP-коды |
| error_namespace | Система или слой, к которому относится обозначение |
| diagnostic_markers | Короткие проверенные фрагменты сообщения для уточнения причины |
| context_required | Необходимость уточнить контекст; не разрешение выдавать ответ без проверки продукта |
| defect_id | Необязательный номер зарегистрированной ошибки разработчика |
| alternative_search_phrases, keywords | Варианты формулировок и слова для поиска |
| workflow | Операция, при которой применима карточка |
| cause, cause_confidence | Объяснение и степень уверенности именно в причине |
| physician_instructions | Один–три безопасных шага врача |
| escalation_instructions | Кому передать вопрос и какие обезличенные сведения сообщить |
| source_urls, source_locator | Точный адрес и место подтверждения в источнике |
| evidence_status, evidence_note | Статус доказательств и важные ограничения |
| confirmed_solution | Есть ли описанный способ действия/исправление, а не только симптом или правило ограничения |
| software_product, software_version | Продукт и версия, к которым относится доказательство |
| local_verification_status | Применимость в целевой больнице; пока везде не проверена |
| source_date, checked_on | Дата источника и дата исследовательской проверки; это разные даты |
| clarifying_questions, safety_note | Уточнения при неоднозначности и запрет опасного повторения операций |

## Как интерпретировать доказательства

«Подтверждено» может означать подтверждённый запрет или историческое ограничение, у которого нет опубликованного решения. Поэтому для ответа нужно читать evidence_note и confirmed_solution вместе. Даже true не означает, что способ проверен в Иванове или применим к любому релизу.

«Возможно» не превращается в точный диагноз сбоя после совпадения поисковой фразы. «Подтверждено пользователем» отделено от документации и ответов разработчика. Все источники по МедФлекс и 1C-MR требуют проверки соответствующего оператора или реализации.

## Предлагаемое поведение поиска

1. Сопоставить точный код, затем текст сообщения и варианты формулировок. Для обычных слов не учитывать регистр и различие е/ё. Номера СЭМД, дефектов и коды сообщений хранить и объяснять отдельно.
2. Проверить операцию, продукт и версию. При неизвестной конфигурации сообщить об этом ограничении. При нескольких совпадениях спросить, где выполняется действие и какие слова сообщения сохранились в памяти.
3. Вернуть заголовок, короткое объяснение, действия и отметку доказательности со ссылкой. Если подтверждённого исправления нет, сообщить это прямо и дать безопасный маршрут эскалации.

Например, «не могу подписать эпикриз» может соответствовать нескольким причинам. Нельзя выбирать одну только по похожему заголовку. «Ошибка 500» не имеет универсального исправления в этой базе. Для VALIDATION_ERROR требуется поясняющий текст после кода.

Локальный HTML реализует простой поиск по фрагментам, а не семантический поиск и не готовый диалоговый движок. Точный код получает приоритет; неизвестные буквенные коды не исправляются нечётким поиском. Для короткого числового запроса сначала ищется статус или код, а запись «№ 101» означает номер карточки. У1-52 также находится как U1-52. Поиск запускается кнопкой или Enter; текст запроса не отправляется на сервер. Проверки сохранены в research/codes-v4/. Пользователь подтвердил открытие предыдущей версии сайта на телефоне; это не испытание в МИС.

## Данные и обновления

Не запрашивать ФИО пациента, дату рождения, номер карты, СНИЛС, полис, медицинские документы или снимки экрана. Не использовать вопрос врача как разрешение подключаться к МИС. Не выполнять назначения, исправления, отправку или подписание из будущего справочного бота.

Редактировать исходные карточки в scripts/build_guide.py , research/continuation_cards.json и scripts/build_code_expansion.py, затем пересобирать представления. CSV содержит те же поля; массивы записаны JSON-строками внутри ячеек, разделитель — точка с запятой, кодировка UTF-8 с BOM. Изменения CSV необходимо переносить в исходный набор перед повторной сборкой, иначе они будут перезаписаны.

Для каждого будущего обновления фиксировать версию программы, адрес доказательства, дату и результат местной проверки на обезличенном учебном сценарии. Не заменять историческое правило новым без сохранения границ применимости.
